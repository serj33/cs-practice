`git diff` показывает различия между двумя версиями файлов.

`git show` показывает информацию о конкретном коммите и изменения, которые были сделаны в этом коммите.

`git log` показывает историю коммитов.

`git log -S"def" --oneline – lab03/calc.py` ищет коммиты, в которых изменилось количество вхождений строки `def` в файле. В нашем файле `def` не использовалось, поэтому изменений с этой строкой не найдено.

`git blame lab03/calc.py` показывает, каким коммитом и автором была добавлена или изменена каждая строка файла. В результате видно, какие строки относятся к коммитам сложения, вычитания и умножения.

git restore lab03/calc.py восстанавливает файл из индекса (staging area), то есть из подготовленной к коммиту версии.

git restore --source=HEAD~2 lab03/calc.py восстанавливает файл из указанного коммита — в данном случае из HEAD~2, то есть из версии на два коммита раньше.

После git restore --source=HEAD~2 в рабочем файле появилась старая версия. После git restore lab03/calc.py мои изменения были отменены, и файл вернулся к версии из индекса. 

`git revert` отменяет изменения указанного коммита, создавая новый коммит. В отличие от `git reset`, он не переписывает историю, поэтому безопасен для уже опубликованной ветки.

Ветка (`branch`) — это отдельная линия разработки в Git. Она позволяет работать над изменениями независимо от `main`, а затем при необходимости объединить изменения с помощью `git merge`.
